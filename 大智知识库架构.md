# 大智回复知识库：架构 · 结构 · 构建方式

本文只描述 **`desktop/` 工程里、通过「大智」唤醒的 AI 会议助手** 所用业务知识库。  
运行态以 `desktop/knowledge/` 为主；研发指南在仓库根 `dev_knowledge/`（会中业务口径不进后者）。

> 改 FAQ / schema / 主进程后，会场需重新执行 `npm run desktop` 才生效。

---

## 1. 定位

| 项    | 说明                                                               |
| ---- | ---------------------------------------------------------------- |
| 工程   | `desktop/`                                                       |
| 产品   | **大智 · AI 会议助手**（听会旁听、呼叫唤醒、口播答复、副驾驶建议）                           |
| 唤醒   | 会中口令如「大智你好」进入咨询；「谢谢大智」继续静默旁听等（详见 `schema/session-commands.json`） |
| 知识目标 | **口径可审、可口播、可复盘补库**；禁止会中现场改写正式事实                                  |
| 非目标  | 研发论文 Wiki（根 `dev_knowledge/wiki`，会中不读）；本文件不描述音频双轨实现细节              |

一句话：**原料只追加 → Wiki 词条为正式口径 → FAQ 做闭题秒答 → 会后从会话/inbox 升格问法。**

## 2. 总体架构

```text
┌─────────────────────────────────────────────────────────────────┐
│  Raw（immutable）                                                │
│  quan-yuan-meiyu.txt · 资料副本 · sessions/*.jsonl               │
└────────────────────────────┬────────────────────────────────────┘
                             │ 人工 / bootstrap / 审定
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  LLM Wiki（正式词条）  knowledge/wiki/                            │
│  concepts/*.md（口播·事实·边界·相关·出处·常见问法）               │
│  index.md · schema.md · log.md                                   │
└───────┬───────────────────────────────┬─────────────────────────┘
        │ 派生 L1                        │ wiki2:sync-domain
        ▼                                ▼
┌──────────────────┐          ┌───────────────────────────────────┐
│ faq-meeting.txt  │          │ knowledge_wiki/（Evidence Wiki2） │
│ L1 闭题秒答      │          │ entities/biz_* · Fast Read 索引   │
└────────┬─────────┘          └─────────────────┬─────────────────┘
         │ 会中 Query                            │ prefetch / 建议卡
         ▼                                       ▼
┌─────────────────────────────────────────────────────────────────┐
│  答法层：L1 FAQ → L2 Wiki+短答 → L3 Wiki+深思                     │
│  成功答后 → inbox/ → 会后 ingest / promote（只追加问法，不改事实）│
└─────────────────────────────────────────────────────────────────┘

旁路配置（非业务话术）：knowledge/schema/*.json
离线增强：knowledge/chains/（连续追问链）· .rag-index.json（语义索引）
```

**会中只做 Query；Ingest / Lint / 升格 / 重建索引一律会后执行。** 知识库不直接决定是否开口（开口由策略引擎 + schema 口令/门控负责）。

## 3. 目录结构

### 3.1 业务知识主目录 `desktop/knowledge/`

| 路径                            | 角色                                             |
| ----------------------------- | ---------------------------------------------- |
| `faq-meeting.txt`             | **L1** 闭题模板；`Q:` 多别名 / `A:` 可 TTS 短答（建议 ≤80 字） |
| `quan-yuan-meiyu.txt`         | 详版原料；缺口时才进向量 / 顾问引用                            |
| `wiki/schema.md`              | 词条模板与 Ingest·Query·Lint 约定                     |
| `wiki/index.md`               | 会中目录：`slug \| 一句话 \| type \| aliases=`         |
| `wiki/concepts/*.md`          | **正式口径词条**                                     |
| `wiki/log.md`                 | Wiki 变更日志                                      |
| `raw/`                        | 原料说明；原始材料只追加不改口径                               |
| `schema/*.json`               | 引擎超参、口令、意图、FAQ 匹配、Dialogue-Meta 等（**无业务长文**）   |
| `sessions/`                   | 本场 `mtg_*.jsonl` + 可选 `*-summary.md`           |
| `inbox/`                      | L2/L3 答后候选、FAQ 候选片段                            |
| `distilled/`                  | 历史「一问一文件」升格；**新沉淀默认进 wiki「常见问法」**              |
| `chains/`                     | 离线蒸馏的连续追问链（不决定开口）                              |
| `.rag-index.json`             | Embedding 本地索引（`npm run rag:index` 生成）         |
| `li-laoshi-system-prompt.txt` | 顾问系统提示（若存在）                                    |

### 3.2 Evidence Wiki 2.0 `desktop/knowledge_wiki/`

与业务 `knowledge/wiki` **分离**：供会中 **Fast Read**（只注入 AI-First Snapshot）与会后 **Slow Write**。

| 路径                | 用途                           |
| ----------------- | ---------------------------- |
| `wiki/entities/`  | 实体页（含 `biz_*`：从 concepts 同步） |
| `wiki/decisions/` | 架构/产品决策页                     |
| `wiki/themes/`    | 跨会主题（Wave F）                 |
| `raw/episodes/`   | 会后原始切片                       |
| `changelog/`      | 冲突消解审计                       |
| `.graph_index/`   | `npm run wiki2:index` 生成，勿手改 |

改 Markdown 后执行 `npm run wiki2:index`；改业务概念页后还需 `npm run wiki2:sync-domain`。

### 3.3 研发知识 `dev_knowledge/`（仓库根，对照）

| 路径 | 会中是否读 |
| ---- | -------- |
| `shared/adr/` · `projects/desktop/` · `wiki/` · `raw/` | **否**（Cursor / 研发） |
| `shared/glossary` ∪ `projects/desktop/glossary` | **是**（ASR 热词，经 `appPaths`） |

## 4. 词条与 FAQ 结构

### 4.1 概念页（`wiki/concepts/{slug}.md`）

```markdown
# 标题

## 口播          ← 会中可朗读；FAQ 的 A 应从这里派生
## 事实          ← 可核对规则/数字；须能回溯 raw
## 边界          ← 禁止承诺、未写明单价、易混点
## 相关          ← [[other-slug]]
## 出处          ← quan-yuan-meiyu.txt / 协议…
## 常见问法      ← 检索别名；Ingest 默认可追加；不覆盖事实
```

`index.md` 行格式：

```text
- slug | 一句话 | type=concept|benefit|ledger|process | aliases=别名1,别名2
```

### 4.2 FAQ（`faq-meeting.txt`）

```text
## Q: 问法 A？ / 同义问法 B？ / …

A: 口播短句（与词条「口播」一致）。
```

匹配权重等超参见 `schema/faq-match.json`（实体加权、最低分等），**不把业务长文写进 schema**。

### 4.3 Wiki2 实体页（四段式）

见 `knowledge_wiki/TEMPLATE.md`：`[1] AI-First Snapshot` → `[2] Active Claims` → `[3] Superseded`。  
`wiki2:sync-domain` 映射：口播 → Snapshot，事实 → Active，边界 → Superseded 摘要。

## 5. 会中答法三层

| 层      | 来源                      | 行为                    |
| ------ | ----------------------- | --------------------- |
| **L1** | `faq-meeting.txt`       | 闭题模板秒答，优先 TTS         |
| **L2** | Wiki 整页 + 短 Chat        | 开放/经营类；成功写入 `inbox/`  |
| **L3** | Wiki 整页 + Deep Thinking | 难例/起死回生；成功写入 `inbox/` |

检索优先级（简化）：

1. FAQ 对齐 / 关键词（`lib/knowledge/corpus.cjs`）  
2. Wiki 目录 + 整页（`lib/knowledge/wiki/`）  
3. 语义 RAG（`lib/knowledge/rag/`，依赖 `.rag-index.json`）  
4. Wiki2 Fast Read（`lib/wiki2/`，建议卡 / prefetch / Catch Me Up）  
5. 连续追问链（`knowledge/chains/`，辅助，不改开口线）

## 6. 构建与维护方式

### 6.1 从零 / 大改原料

1. 把详版、协议等放入 / 追加 `quan-yuan-meiyu.txt`（及 `raw/` 说明），**不直接改正式口径文件冒充原料**。  
2. 人工或 `npm run knowledge:wiki:bootstrap` 生成/更新 `wiki/concepts/` 与 `index.md`。  
3. 从词条「口播」整理 `faq-meeting.txt`（避免两套口径）。  
4. `npm run rag:index`；`npm run wiki2:sync-domain` → `npm run wiki2:index`。  
5. `npm run knowledge:wiki:lint` 查矛盾数字、断链、FAQ 与口播不一致。

### 6.2 会后闭环（主路径）

```text
开会 → sessions/*.jsonl
     → L2/L3 成功答 → inbox/
     → 会后审定：
          knowledge:wiki:ingest     # inbox → 概念页「常见问法」（不改事实）
          knowledge:promote:faq     # 短答升格进 FAQ（A=词条口播）
          knowledge:session[:faq]   # 从最新/全部会话升格
          knowledge:wiki:lint
          rag:index / wiki2:sync-domain / wiki2:index
```

常用命令（均在 `desktop/` 下）：

| 命令                                            | 作用                    |
| --------------------------------------------- | --------------------- |
| `npm run knowledge:wiki:ingest`               | inbox → 常见问法          |
| `npm run knowledge:wiki:ingest:dry`           | 干跑                    |
| `npm run knowledge:promote:faq`               | 升格 FAQ                |
| `npm run knowledge:promote:dry`               | 升格干跑                  |
| `npm run knowledge:session` / `:faq` / `:all` | 会话升格                  |
| `npm run knowledge:wiki:lint`                 | 词条 / FAQ 一致性          |
| `npm run knowledge:wiki:bootstrap`            | Wiki 引导构建             |
| `npm run rag:index`                           | 重建语义索引                |
| `npm run knowledge:distill`                   | 离线连续追问链               |
| `npm run wiki2:index`                         | 重建 Wiki2 图索引          |
| `npm run wiki2:sync-domain`                   | concepts → `biz_*` 实体 |
| `npm run wiki2:ingest` / `:apply`             | Episode 摄入（默认 dry）    |
| `npm run wiki2:from-session`                  | 会话 → Episode          |
| `npm run wiki2:themes[:write]`                | 主题编译                  |

### 6.3 硬规则

1. **数字只能来自「事实」或 raw**；L2/L3 成功回答**不得**自动改写「事实 / 口播 / 边界」。  
2. Ingest 对已有词条默认**只追加「常见问法」**；覆盖事实必须人工改文件。  
3. FAQ 的 A **应从词条口播派生**，禁止 FAQ 与 Wiki 两套说法。  
4. **会中不做 Ingest**；超时用不现场编译的词条口播。  
5. `schema/` 只放模式与数字集合；业务说法进 FAQ / Wiki。  
6. `chains/` 会中不自动改写 FAQ；升格仍走 promote。  
7. 知识库**不决定开口**；半双工 / 口令 / Meta 在 schema + 策略引擎。

## 8. 与会中行为的关系

大智作为会议助手时：

- **旁听（默认）**：记录会话；知识库待命，不抢答。  
- **唤醒咨询**：命中 FAQ / Wiki / RAG 后口播；难例走 L2/L3，成功写入 `inbox/`。  
- **副驾驶**：旁路建议卡可走 Wiki2 Fast Read；不占麦。  
- **会后**：从 `sessions/`、`inbox/` 升格问法，补强下场 L1/L2。

闭环：

```text
上场答 → inbox 记缺口 → 复盘补答 → 写入 FAQ/Wiki → 下场更稳
```

**本文件只固定「答复用知识」怎么分层与构建**，不描述 decideSpeak / 半双工实现。

## 9. 速查：改什么、跑什么

| 你改了什么                               | 接着跑                                                                                    |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| `faq-meeting.txt` / `schema/*.json` | 重启 `npm run desktop`                                                                   |
| `wiki/concepts/*.md`                | `knowledge:wiki:lint` → `rag:index` → `wiki2:sync-domain` → `wiki2:index` → 重启 desktop |
| 仅 `knowledge_wiki/**/*.md`          | `wiki2:index`                                                                          |
| 新会话要沉淀问法                            | `knowledge:session:faq` 或 ingest + promote:faq                                         |
| 详版 raw 大更新                          | 人工改词条事实 → 同步 FAQ 口播 → lint + 双索引                                                       |

---

**口号对齐**：答过的要入库，提过的问法要可检索；正式事实只经人工改词条，不经会中模型静默改写。
