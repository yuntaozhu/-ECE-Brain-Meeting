# 星耘 · 会场智能体产品介绍

**定位**：听得见、答得稳、跟得上的 AI 会场伙伴。  
**工作跟进内核**：[KaibanJS](https://www.kaibanjs.com/)（Agent / Task / Team + Kaiban Board）——用看板把「答疑、开会、日常碎片」变成可编排、可观察、可闭环的多智能体工作流。

---

## 一句话

星耘在会场开口、在微信收碎片；**KaibanJS 看板负责把每件事从「提到」推到「做完」**，并驱动会后复盘与知识更新。

---

## 为什么必须用 KaibanJS 跟进

普通纪要只「记过」；项目组要的是持续交付：

| 痛点 | 没有看板跟进 | 有 KaibanJS |
|------|--------------|-------------|
| 会上拍了板 | 散落在转写里 | 自动生成 Task，进待办列 |
| 客服没答好 | 靠人记得补 | Task「补口径 / 入库」可指派、可验收 |
| 微信一句话约定 | 聊过就算 | 碎片进 Board，状态可见 |
| 跨场会议 | 每场从零 | 同一 Team 工作流跨会续跑 |
| 协作透明 | 只有日志 | Kaiban Board 像 Trello，给人和 AI 一起看 |

KaibanJS 提供：

- **Agent**：星耘主持、知识复盘、待办催办等角色可编排  
- **Task**：清晰指令、预期结果、负责人（人或智能体）  
- **Team**：多角色协同完成一场会 / 一周工作  
- **Kaiban Board**：待办 → 进行中 → 待验收 → 完成，实时可视化、可分享  

> 星耘负责「现场能力」；KaibanJS 负责「跟进与编排」。二者一体，才是可运营的产品，而不是单次聊天。

---

## 三大能力（均挂在 Kaiban 工作流上）

### 1. 行业 AI 客服：会答 + 复盘补库

适用：招商说明、园所答疑、**农业 / 产业 AI 客服**等口径敏感场景。

**现场（星耘）**

- 听写提问，按 FAQ / Wiki 口径口播；敏感题不编造报价与承诺  
- 副驾驶旁路建议（推进 / 风险 / 反问），不抢麦  
- 记得上一问、可催答、可纠偏  

**跟进（KaibanJS）**

| 看板列 | 典型 Task |
|--------|-----------|
| 待复盘 | 本场「未答 / 答偏 / 用户不满意」问题卡片 |
| 复盘中 | 大模型 + 人工一起补完整答法 |
| 待入库 | 校验通过的口径，写入 FAQ / 追问链 |
| 已上线 | 下场会自动可用 |

**闭环**：上场答 → Board 记缺口 → Team 复盘补答 → 知识更新 → 下一场更稳。  
「没遇到过的问题」变成可跟踪的知识 Task，而不是一次性尴尬。

---

### 2. 会议主持：持续会务 = 持续看板

星耘进会主持；**每一场会议对应一套（或延续同一套）Kaiban Team 工作流**。

**现场（星耘）**

- 唤醒应答、议程拉回、半双工不抢人  
- 本场转写、提问回顾、速记 / 速览  

**跟进（KaibanJS）**

```text
议题池(Backlog) → 本场进行中 → 已决议 → 待回访 / 跨会续议 → 关闭
```

- 决议自动落成 Task（谁做、何时验、关联哪次会议）  
- 未答完问题不消失，留在「待回访」等下一场再开  
- A2A 可观察：Director / Meeting / Knowledge 等 Agent 协作轨迹可上 Board  
- 跨会不换板：同一项目多场会议，看板状态连续，而不是每场清零  

**价值**：会议从活动变成**项目推进节奏**——拍板、欠账、下次先开哪张卡，人和 AI 共用一块板。

---

### 3. 日常工作管理：微信进板，通话办结

碎片发生在微信；办结要看得见。

**入口**

- 微信开启 / 群消息一句话 → 生成 Task 进 Backlog  
- 群通话旁听 → 抽出约定、待办、风险，挂到对应列  

**跟进（KaibanJS）**

- 限制在制品（WIP）：避免「记了一堆从不推进」  
- 状态流转显式：待办 → 办理中 → 待确认 → 完成  
- 可把日常 Task 升级为「客服补库」或「下会议题」——同一 Board，三类工作互通  

**价值**：「聊过」变成「进板、有主、能催、可验收」。

## Kaiban 上的示例 Team（示意）

不必对外展示代码；对内编排可理解为：

| Agent | 职责 | 产出 Task 示例 |
|-------|------|----------------|
| 会场主持 Agent | 听会、口播、拉回议程 | 「本场未答：优惠政策」 |
| 知识复盘 Agent | 对照 FAQ，起草补答 | 「候选口径待审核」 |
| 会务跟进 Agent | 决议拆解、跨会提醒 | 「回访张园长：落地清单」 |
| 日常助理 Agent | 微信碎片分拣 | 「群约定：周三发资料」 |

人类在 Board 上验收；验收通过才入库或关闭——**人机协同，而不是全自动乱写知识**。

## 和「只会聊天的大模型」差在哪

| | 普通大模型 | 星耘 + KaibanJS |
|--|------------|-----------------|
| 现场 | 要粘贴提问 | 进会听写口播 |
| 口径 | 易发挥 | 知识库优先，可坦诚不编 |
| 记忆 | 窗口即忘 | Focus + 本场记录 |
| 跟进 | 无 | **看板 Task 全生命周期** |
| 成长 | 改提示词 | 复盘 Team → 入库 → 上场 |
| 透明 | 黑盒对话 | **Kaiban Board 可视、可分享** |

## 落地节奏（建议）

1. **会场就绪**：星耘桌面端听写 / 口播 / 副驾驶  
2. **Board 就绪**：KaibanJS Team + Board，对接会后事件（未答、决议、碎片）  
3. **客服闭环**：未答好问题 → 复盘列 → 入库列 → 回归冒烟  
4. **会务连续**：项目级看板跨会，待回访自动进下场议程  
5. **微信延伸**：碎片与群通话进同一 Board，WIP 可控  

---

## 适合谁

- 农业 / 产业 **AI 客服**要持续补库、要跟进投诉与未覆盖题  
- 招商与培训会要**跨场跟进**，不能一场一清  
- 项目组要用看板管「谁欠什么」  
- 微信协作重、需要把通话约定变成可验收工作项的团队
